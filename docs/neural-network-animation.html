Q · K · V Projections

The core idea

Every input token (a board square, 256-dim) is linearly projected into three vectors — Query, Key, and Value — each 32-dim for one head. These weight matrices are learned by backprop and are unique to each head and each block.

Q

Query — “What am I looking for?” This square asks: which other squares should I attend to?

K

Key — “What can I be found by?” Each square broadcasts what kind of query it should match.

V

Value — “What do I share?” The actual content a square contributes when another square attends to it.

Projection formulas

—Q = X ⋅ WQ  [65×256] · [256×32] → [65×32]
—K = X ⋅ WK  [65×256] · [256×32] → [65×32]
—V = X ⋅ WV  [65×256] · [256×32] → [65×32]

WQ, WK, WV are trainable matrices — a set of three for every head in every Transformer block.

The Attention Score Formula

Step by step

1.S  = Q · KT  [65×32] · [32×65] → [65×65] raw scores
2.S  /= √32  scale by √dk to stabilise softmax
3.A  = softmax(S) row-wise  each row sums to 1.0
4.out = A · V  [65×65] · [65×32] → [65×32]

What does S[i, j] mean?

Score S[i,j] = Qi · Kj measures how relevant token j is to token i. A high score means: “square i should borrow a lot from square j's Value.” After softmax, row i of A is a probability distribution that weights the 65 V rows.

Why divide by √32?

For high-dimensional vectors the dot product magnitude grows with dimension — roughly proportional to √dk. Without scaling, scores become very large, softmax squashes nearly all weight onto one token, and gradients vanish. Dividing by √32 ≈ 5.66 keeps the scores in a range where softmax stays informative.

Output is a weighted sum of Values

Row i of the output = ∑j A[i,j] · Vj. Token i gathers information from every other token, proportionally to attention weight. Tokens with high scores share more of their Value vector. This is how a bishop on b2 can “see” a pawn on g7 through the attention matrix, even though they share no convolution kernel.

Why Multi-Head Attention?

The idea

Instead of one attention with dk=256, we run 8 independent attentions with dk=32 in parallel. Each head has its own WQ, WK, WV weights and learns to attend to different relationships at the same time — something a single head cannot do.

Head 1

Rook file control — which column does a rook dominate?

Head 2

King safety — proximity of attacking pieces to each king.

Head 3

Pawn structure — chains, passed pawns, isolated pawns.

Head 4

Piece coordination — knight+bishop battery patterns.

Head 5

Diagonal influence — bishop long-range diagonals.

Head 6

Mobility — squares each piece can reach in one move.

Head 7

Defended squares — which squares are protected by each side.

Head 8

Open files and ranks — unobstructed lines for queens/rooks.

Concatenation and final projection

—concat(h1, …, h8)  [65 × (8×32)] = [65×256]
—out = concat · WO  [65×256] · [256×256] → [65×256]

WO mixes information across all heads. The output is 65×256 — exactly the same shape as the input — which is why the residual connection (x + sublayer(x)) works without any reshape.

Feed-Forward Network (FFN)

Structure — two linear layers with GELU

After attention gathers context from other squares, each token passes through an independent two-layer network. All 65 tokens share the same W1/W2 weights, but each token’s distinct values produce a different output.

1.h  = GELU( x · W1 + b1 )  [65×256] · [256×1024] → [65×1024]
2.out = h · W2 + b2      [65×1024] · [1024×256] → [65×256]

Why expand to 1024 first?

The 4× expansion (256→1024) gives each token enough “working memory” to form rich intermediate features before compressing back to 256. The expanded layer can represent combinations of features that cannot be expressed in 256 dimensions directly. This 4× ratio is a standard Transformer design choice used in GPT, BERT, and ViT.

GELU vs ReLU

GELU (Gaussian Error Linear Unit) is a smooth activation: GELU(x) = x · Φ(x) where Φ is the Gaussian CDF. Unlike ReLU which hard-zeros all negatives, GELU partially passes small negatives, producing smoother gradients and faster convergence in deep Transformers. It is the default activation in GPT-2 and later.

Role vs attention — routing vs thinking

Attention answers “which squares to look at.” FFN answers “what to conclude from that.” Attention is the routing mechanism; FFN is the computation mechanism — a small per-token network that digests the gathered context into a new representation.

Parameter count

—W1 [256×1024] + W2 [1024×256] + biases ≈ 525K params per block
—4 blocks × 525K ≈ 2.1M params in FFN layers alone

FFN accounts for the majority of the Transformer’s parameters — roughly twice as many as the attention projections.

Layer Normalisation (LayerNorm)

The formula

1.μ  = mean( x )  mean over the 256 features of one token
2.σ  = std( x )   std over the 256 features of one token
3.LN(x) = γ · (x − μ) / (σ + ε) + β

γ (scale) and β (shift) are learnable parameters — 256 each. ε = 1e−5 prevents division by zero. γ and β let the network undo the normalisation if needed.

Applied twice per block

1.x′  = LN( x + MHA(x) )  after attention residual add
2.x′′ = LN( x′ + FFN(x′) )  after FFN residual add

This is Post-LN style (original Transformer). The input to the next block is x′′, which has been normalised after every sublayer.

Why not BatchNorm?

BatchNorm normalises across the batch dimension — it needs statistics from multiple samples simultaneously. LayerNorm normalises across the feature dimension of a single token, independently of all other tokens and samples. This makes LayerNorm batch-size agnostic — it works identically during training and inference, even with a single position.

Why normalise at all?

The residual sum x + sublayer(x) can have any scale — it grows as signals accumulate across 4 blocks. Without normalisation, activations drift: small values vanish into irrelevance, large values saturate non-linearities. LayerNorm re-centres each token’s 256 features to μ≈0, σ≈1 before the learned γ/β rescales them. This keeps gradients healthy and training stable across all 4 stacked Transformer blocks.

What Batch Normalization Does

The problem it solves

During training, each Conv2d layer changes its weights. As a result the distribution of activations it feeds into the next layer keeps shifting — a phenomenon called Internal Covariate Shift. The next layer must constantly re-adapt to a moving target, slowing convergence and forcing tiny learning rates.

The fix: normalise every channel

After the convolution produces a 256 × 8 × 8 output, BatchNorm takes each of the 256 channels independently and rescales its values so that, across the current mini-batch, the channel has mean ≈ 0 and variance ≈ 1. It then applies a learned scale γ and shift β so the network can undo the normalisation if needed.

What “across the batch” means here

For a conv output shaped [B × C × H × W], BatchNorm computes statistics over B × H × W values — every sample in the batch and every spatial position — separately for each of the C=256 channels. So channel 17’s mean and variance are computed from all 8×8=64 spatial pixels across all B board positions in the mini-batch.

The BatchNorm Formula

Four steps per channel c

1.μc  = 1⁄B⋅H⋅W ∑ xb,c,h,w  mean over batch & spatial
2.σ2c = 1⁄B⋅H⋅W ∑ (xb,c,h,w − μc)2  variance
3.x̂b,c,h,w = (xb,c,h,w − μc) / √(σ2c + ε)  normalise
4.yb,c,h,w = γc ⋅ x̂b,c,h,w + βc  scale & shift (learned)

Learnable parameters

γ (scale) and β (shift) are vectors of length C=256 — one scalar per channel. They are trained by backprop. If the network finds that channel 42 should not be normalised, it can set γ42 ≈ large and β42 ≈ original mean, effectively recovering the pre-normalised signal.

Inference: running statistics

At inference time there may be only a single board position (B=1), so batch statistics would be meaningless. BatchNorm solves this by maintaining exponential moving averages of μ and σ2 during training. At inference those frozen running stats replace the per-batch computation, making the layer a fixed affine transform: y = γ ⋅ (x − μrun) / σrun + β.

Parameter count for this layer

—γ [256] + β [256]  =  512 trainable params
—running mean [256] + running var [256]  =  512 buffers (not trained)
Why BatchNorm Helps Training

Smoother loss landscape

Research (Santurkar et al., 2018) showed that BatchNorm’s primary benefit is not reducing internal covariate shift per se, but smoothing the loss landscape. Normalised activations mean gradient magnitudes are more predictable across layers — the network can take larger, more confident gradient steps without the loss suddenly spiking.

Allows higher learning rates

Without BatchNorm, a high learning rate can push activations into saturation regions where gradients vanish (e.g., large inputs to ReLU produce dead neurons; large inputs to sigmoid produce near-zero gradients). BatchNorm re-centres activations so a much larger range of learning rates is safely usable — typically 5–10× higher, cutting training time proportionally.

Mild regularisation effect

Because statistics are computed per mini-batch, the normalisation adds a small amount of noise (the batch mean and variance vary between batches). This acts like a weak regulariser, sometimes reducing the need for Dropout in convolutional networks. The chess CNN uses no Dropout in the backbone — BatchNorm provides enough implicit regularisation.

Interplay with ReLU here

The order Conv → BN → ReLU matters. BatchNorm centres the conv output around 0 before ReLU sees it. Since ReLU zeros everything < 0, starting from mean ≈ 0 means roughly half the neurons are active on each forward pass — a healthy activation density. If BN came after ReLU, the already-non-negative values would be shifted/scaled unnecessarily.

BatchNorm vs LayerNorm — Why Each Network Uses Its Own

The key axis of normalisation

BNNormalise over B × H × W  per channel — needs a batch
LNNormalise over features    per token — works for B=1

Why BatchNorm suits the CNN backbone

The CNN processes a mini-batch of 256×8×8 feature maps. Here channel is the meaningful grouping: channel 42 always represents the same learned feature detector (e.g., “pawn chain on the a-file”). Normalising across B×H×W stabilises that detector’s output distribution without mixing it with unrelated channels.

Why LayerNorm suits the Transformer

The Transformer operates on token sequences of shape [65×256]. The meaningful grouping is now the 256 features of a single token. There is no natural spatial dimension to average over, and at inference the sequence length may vary. LayerNorm normalises each token’s 256 features independently — no cross-sample statistics needed, so it works identically with B=1.

Summary comparison

BN

Per-channel, needs batch · Ideal for CNNs · Running stats at inference · ~512 params for 256ch

LN

Per-token, batch-agnostic · Ideal for Transformers & RNNs · Same formula at train/infer · ~512 params for 256-dim

What is Mean Squared Error?

The single job of a loss function

After the forward pass produces ŷ ∈ (−1, +1), we need a single number that quantifies how wrong the prediction is. This number — the loss — must be differentiable so that backpropagation can compute ∂L/∂W for every weight in the network.

MSE in one sentence

MSE measures the average squared distance between the network’s prediction ŷ and the true label y, averaged over the mini-batch of B positions.

—L = 1⁄B ∑i=1B (ŷi − yi)2

Training labels

Labels come from self-play game outcomes: y = +1 (White wins), y = 0 (Draw), y = −1 (Black wins). The same position can appear multiple times in different games with different outcomes — the network learns the expected outcome, which is a continuous value between −1 and +1.

The MSE Formula, Step by Step

From one sample to a batch

1.residuali  = ŷi − yi  signed error for sample i
2.ei  = residuali2  squared — always ≥ 0, penalises large errors more
3.L = 1⁄B ∑i ei  mean over the batch

The gradient of MSE — what backprop gets

—∂L/∂ŷi  = 2⁄B ⋅ (ŷi − yi)

The gradient is simply proportional to the residual. A prediction of +0.8 against a target of −1 gives residual = +1.8 → a large gradient that pushes the weight update hard. A prediction close to the target gives a small gradient → small update. This is why MSE training naturally “slows down” as the network improves.

Squaring vs absolute value

|residual| (MAE) is differentiable everywhere except 0 and treats all errors equally. residual² (MSE) amplifies large errors quadratically — a residual of 2 contributes 4× as much as a residual of 1. For chess, where a completely wrong sign prediction (+1 vs −1) is catastrophic, the extra penalty on large errors is desirable.

Why MSE for Chess Evaluation?

The output is a continuous regression target

Unlike classification (discrete class probabilities), our output is a real number in (−1, +1). MSE is the natural loss for continuous regression. Cross-entropy would require discretising the outcome into bins, losing the natural ordering (+0.7 is better for White than +0.3).

Noisy labels are fine

Self-play game outcomes are very noisy — a position that is theoretically +1 might result in a draw due to later mistakes. MSE’s averaging over a mini-batch naturally handles this: with enough samples the network learns the expected value. The squared term means occasional catastrophically-wrong game outcomes get appropriately high loss.

tanh output pairs naturally with MSE

The final tanh squashes the linear output into (−1, +1), matching the label range exactly. MSE loss on a tanh output never produces exploding gradients: when the prediction saturates near ±1, the tanh gradient (1−tanh²) shrinks, and the MSE gradient (residual) also shrinks because the prediction is near the boundary of the label range.

The Loss Landscape

What the landscape is

If you could plot loss L as a function of all ~6M weights simultaneously, you would get a high-dimensional surface. Training is the process of finding a low point on that surface. MSE produces a smooth, convex landscape locally around any minimum, which makes gradient descent well-behaved in the final stages of training.

Saddle points and plateaus

In high-dimensional spaces, the loss landscape has many saddle points — directions where the curvature is positive (local min) and others where it is negative (local max). Pure gradient descent can stall here. Adam’s per-parameter momentum and variance estimates help escape saddle points faster than SGD.

Batch size and loss estimation

Computing MSE over all training positions at once (full-batch) would give the true gradient but is too slow. With mini-batches of e.g. 512 positions, the gradient is estimated. Smaller batches = noisier estimates = more exploration of the landscape. Larger batches = smoother gradient = more direct descent. The chess network uses moderate batch sizes to balance these effects.

Backpropagation & the Chain Rule

What backprop computes

Backpropagation is an efficient algorithm for computing ∂L/∂W for every weight W in the network simultaneously. It applies the chain rule of calculus, working backwards from the loss to the inputs — one layer at a time — reusing intermediate computations.

The chain rule

—if L depends on z which depends on W:
—∂L/∂W  = ∂L/∂z ⋅ ∂z/∂W
—for a chain of n layers: ∂L/∂W1 = ∂L/∂an ⋅ ∂an/∂an-1 ⋅ … ⋅ ∂a2/∂W1

Why backprop is efficient

A naïve implementation would recompute the chain for every weight separately — O(parameters × layers) cost. Backprop instead makes one backwards pass: it computes ∂L/∂ak for each layer’s pre-activation ak, caches it, and then all weights at that layer share the same cached upstream gradient. Total cost: one forward pass + one backward pass.

Step through this network

←Loss  ←  ∂L/∂ŷ = 2(ŷ − y)/B
←tanh ←  multiply by (1 − tanh²)
←Linear(256→1) ←  gradient w.r.t. 256 weights
←Transformer ×4 ←  through LN, FFN, MHA residuals
←CNN backbone ←  through 8 residual blocks
Gradient Flow Through Each Layer

tanh gradient

—d/dx tanh(x)  = 1 − tanh²(x)  range (0, 1]

Near saturation (|x| large), tanh gradient → 0. But since the linear layer before tanh outputs a raw scalar and the labels are in (−1,+1), the output rarely saturates during training — gradient stays near 1.

Linear layer gradient

—∂L/∂W = δ ⋅ xT  outer product of upstream gradient and input
—∂L/∂x = WT ⋅ δ  gradient passed to previous layer

LayerNorm gradient

LayerNorm normalises across 256 features, so its gradient couples all 256 dimensions together. The learnable γ/β parameters receive ∂L/∂γc = ∑b δb,c ⋅ x̂b,c — summed over the batch. This is why LayerNorm parameters update quickly despite being only 512 params: every position in every batch contributes to their gradient.

Attention gradient (key insight)

The attention score S = QKT/√dk involves a matrix multiplication and softmax. The softmax Jacobian is ∂softmax/∂S = diag(A) − A·AT — a full 65×65 matrix. This is why backprop through attention is memory-intensive: it needs the full attention matrix A cached from the forward pass.

Vanishing Gradients

The problem in deep networks

Each layer multiplies the gradient by its local Jacobian. If those Jacobians have eigenvalues < 1, the gradient shrinks exponentially as it propagates backwards. By layer 1, the gradient may be 10−8 or smaller — too small to update weights meaningfully. This makes training deep networks nearly impossible without mitigation.

Magnitude analysis for this network

—Value Head: gradient scale ~1  (tanh derivative ≈ 1 near 0)
—Transformer ×4: each block adds, doesn’t multiply  (residuals!)
—CNN ×8 blocks: same — output = F(x) + x
—Without residuals: ~0.720 ≈ 0.0008 signal left

Why sigmoid/tanh as hidden activations were abandoned

Early deep nets used sigmoid or tanh in hidden layers. Their derivative saturates to 0 for large inputs. With 20 hidden layers, the product of 20 near-zero derivatives made the first layers untrainable. ReLU (derivative = 1 for x > 0) fixed this — and residual connections fixed the remaining depth problem.

How Residual Connections Solve Vanishing Gradients

The residual gradient identity

—forward:  out = F(x) + x
—backward: ∂out/∂x = ∂F(x)/∂x + 1

The +1 term means the gradient always has a direct highway back through the skip connection, regardless of what F(x) learned. Even if ∂F/∂x shrinks to near zero, the overall gradient stays at least 1.

Applied to this network

Both the CNN backbone (8 residual blocks) and the Transformer (4 blocks, each with two residual adds) use this pattern. The gradient flowing from the value head back to the very first convolution always has an unobstructed path through all the skip connections — even after 20+ sequential operations. This is what makes training a ~6M parameter network feasible.

LayerNorm also helps

LayerNorm normalises the scale of activations entering each sublayer. Without it, residual outputs accumulate scale — after 4 Transformer blocks the activations might have variance 4× the input, pushing downstream layers into saturation. LayerNorm keeps each block’s input well-conditioned regardless of depth.

What Adam Does

The problem with plain gradient descent

Vanilla SGD updates every weight by the same learning rate: θ ← θ − α ⋅ g. Two problems arise: (1) weights with noisy, inconsistent gradients take huge steps in the wrong direction; (2) weights with consistent but small gradients learn too slowly. The optimal learning rate is different for every weight.

Adam’s two ideas

1.Momentum (m): exponential moving average of gradients. Smooths out noise — the step direction is a running average, not a single noisy estimate.
2.Adaptive scale (v): exponential moving average of gradient2. Dividing by √v̂ gives a per-weight learning rate: small step for high-variance weights, large step for stable weights.

Intuition for chess training

The attention weight matrices receive gradients from 65×65 attention patterns — extremely noisy. The value head’s single linear layer receives a clean, consistent gradient. Adam automatically gives the attention weights a smaller effective learning rate (their v is large) and the value head a larger one, without any manual per-layer tuning.

The Adam Algorithm

Per-parameter update (one step t)

1.gt  = ∂L/∂θ  gradient from backprop
2.mt = β1⋅mt-1 + (1−β1)⋅gt  1st moment (momentum), β1=0.9
3.vt = β2⋅vt-1 + (1−β2)⋅gt2  2nd moment (variance), β2=0.999
4.m̂t = mt/(1−β1t)  bias correction for early steps
5.v̂t = vt/(1−β2t)  bias correction
6.θt = θt-1 − α ⋅ m̂t / (√v̂t + ε)  weight update

Why bias correction?

At step 1, m0 and v0 are initialised to zero. Without correction, the first few steps would use heavily under-estimated m and v, leading to unreasonably large updates. The (1−βt) denominator grows from near-0 toward 1 as t increases, correcting the initialisation bias. After ~100 steps (for β1=0.9), the correction is negligible.

Memory cost

—Adam stores m and v for every parameter: 3× memory vs SGD
—~6M params × 3 × 4 bytes = ~72 MB for optimizer state
Adam Hyperparameters

Learning rate α

Typical default: α = 1e−3. The most sensitive hyperparameter. Too high → loss oscillates or diverges. Too low → training is very slow. For this chess network, α is often warmed up (from 0 to peak over the first few thousand steps) then decayed via cosine schedule.

β1, β2 — decay rates

β1=0.9Momentum half-life ≈ 7 steps. Gradient signal has a memory of about 7 recent batches.
β2=0.999Variance half-life ≈ 700 steps. Variance estimate changes slowly — stable per-weight scale.

β2=0.999 vs 0.99: a larger β2 makes the variance estimate more stable (less noisy) but slower to adapt to sudden gradient changes (e.g., after a learning rate increase). For transformers, 0.999 is the community default.

ε — numerical stability

ε = 1e−8 prevents division by zero when v̂ ≈ 0. For transformers with fp16 training, ε is often increased to 1e−6 to avoid numerical issues with half-precision arithmetic. Since this model trains in fp32, 1e−8 is fine.

Weight decay (AdamW)

Standard Adam couples weight decay into the gradient, distorting the adaptive scale. AdamW (a common variant) applies weight decay directly to the weights: θ ← θ(1 − λ) − Adam update. This prevents large weights without interfering with Adam’s per-parameter scaling, and is the standard for Transformer training.

Adam vs SGD

Why Adam converges faster on Transformers

Transformer attention weights receive gradients that vary wildly across heads and layers. SGD with a global learning rate either overshoots noisy weights or undershoots stable ones. Adam’s per-weight learning rate (α/√v̂) adapts: it shrinks for noisy weights and grows for stable ones, navigating the loss landscape more efficiently.

Comparison table

SGD + momentum

Simple · Low memory · Often better final accuracy on CNNs · Needs careful LR tuning · Slow on transformers

Adam

Interesting subtlety: CNN backbone uses BN, which changes Adam’s behaviour

BatchNorm’s normalisation makes the loss surface more isotropic (similar curvature in all directions). On such surfaces, SGD and Adam perform similarly. The Transformer backbone (with LayerNorm) has a more anisotropic landscape — this is where Adam’s adaptive scaling gives the biggest advantage over SGD.
