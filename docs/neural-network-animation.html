Q · K · V Projections

The core idea

Every input token (a board square, 256-dim) is linearly projected into three vectors — Query, Key, and Value — each 32-dim for one head. These weight matrices are learned by backprop and are unique to each head and each block.

Q

Query — “What am I looking for?” This square asks: which other squares should I attend to?

K

Key — “What can I be found by?” Each square broadcasts what kind of query it should match.

V

Value — “What do I share?” The actual content a square contributes when another square attends to it.

Projection formulas

—Q = X ⋅ WQ  [65×256] · [256×32] → [65×32]
—K = X ⋅ WK  [65×256] · [256×32] → [65×32]
—V = X ⋅ WV  [65×256] · [256×32] → [65×32]

WQ, WK, WV are trainable matrices — a set of three for every head in every Transformer block.

The Attention Score Formula

Step by step

1.S  = Q · KT  [65×32] · [32×65] → [65×65] raw scores
2.S  /= √32  scale by √dk to stabilise softmax
3.A  = softmax(S) row-wise  each row sums to 1.0
4.out = A · V  [65×65] · [65×32] → [65×32]

What does S[i, j] mean?

Score S[i,j] = Qi · Kj measures how relevant token j is to token i. A high score means: “square i should borrow a lot from square j's Value.” After softmax, row i of A is a probability distribution that weights the 65 V rows.

Why divide by √32?

For high-dimensional vectors the dot product magnitude grows with dimension — roughly proportional to √dk. Without scaling, scores become very large, softmax squashes nearly all weight onto one token, and gradients vanish. Dividing by √32 ≈ 5.66 keeps the scores in a range where softmax stays informative.

Output is a weighted sum of Values

Row i of the output = ∑j A[i,j] · Vj. Token i gathers information from every other token, proportionally to attention weight. Tokens with high scores share more of their Value vector. This is how a bishop on b2 can “see” a pawn on g7 through the attention matrix, even though they share no convolution kernel.

Why Multi-Head Attention?

The idea

Instead of one attention with dk=256, we run 8 independent attentions with dk=32 in parallel. Each head has its own WQ, WK, WV weights and learns to attend to different relationships at the same time — something a single head cannot do.

Head 1

Rook file control — which column does a rook dominate?

Head 2

King safety — proximity of attacking pieces to each king.

Head 3

Pawn structure — chains, passed pawns, isolated pawns.

Head 4

Piece coordination — knight+bishop battery patterns.

Head 5

Diagonal influence — bishop long-range diagonals.

Head 6

Mobility — squares each piece can reach in one move.

Head 7

Defended squares — which squares are protected by each side.

Head 8

Open files and ranks — unobstructed lines for queens/rooks.

Concatenation and final projection

—concat(h1, …, h8)  [65 × (8×32)] = [65×256]
—out = concat · WO  [65×256] · [256×256] → [65×256]

WO mixes information across all heads. The output is 65×256 — exactly the same shape as the input — which is why the residual connection (x + sublayer(x)) works without any reshape.

Feed-Forward Network (FFN)

Structure — two linear layers with GELU

After attention gathers context from other squares, each token passes through an independent two-layer network. All 65 tokens share the same W1/W2 weights, but each token’s distinct values produce a different output.

1.h  = GELU( x · W1 + b1 )  [65×256] · [256×1024] → [65×1024]
2.out = h · W2 + b2      [65×1024] · [1024×256] → [65×256]

Why expand to 1024 first?

The 4× expansion (256→1024) gives each token enough “working memory” to form rich intermediate features before compressing back to 256. The expanded layer can represent combinations of features that cannot be expressed in 256 dimensions directly. This 4× ratio is a standard Transformer design choice used in GPT, BERT, and ViT.

GELU vs ReLU

GELU (Gaussian Error Linear Unit) is a smooth activation: GELU(x) = x · Φ(x) where Φ is the Gaussian CDF. Unlike ReLU which hard-zeros all negatives, GELU partially passes small negatives, producing smoother gradients and faster convergence in deep Transformers. It is the default activation in GPT-2 and later.

Role vs attention — routing vs thinking

Attention answers “which squares to look at.” FFN answers “what to conclude from that.” Attention is the routing mechanism; FFN is the computation mechanism — a small per-token network that digests the gathered context into a new representation.

Parameter count

—W1 [256×1024] + W2 [1024×256] + biases ≈ 525K params per block
—4 blocks × 525K ≈ 2.1M params in FFN layers alone

FFN accounts for the majority of the Transformer’s parameters — roughly twice as many as the attention projections.

Layer Normalisation (LayerNorm)

The formula

1.μ  = mean( x )  mean over the 256 features of one token
2.σ  = std( x )   std over the 256 features of one token
3.LN(x) = γ · (x − μ) / (σ + ε) + β

γ (scale) and β (shift) are learnable parameters — 256 each. ε = 1e−5 prevents division by zero. γ and β let the network undo the normalisation if needed.

Applied twice per block

1.x′  = LN( x + MHA(x) )  after attention residual add
2.x′′ = LN( x′ + FFN(x′) )  after FFN residual add

This is Post-LN style (original Transformer). The input to the next block is x′′, which has been normalised after every sublayer.

Why not BatchNorm?

BatchNorm normalises across the batch dimension — it needs statistics from multiple samples simultaneously. LayerNorm normalises across the feature dimension of a single token, independently of all other tokens and samples. This makes LayerNorm batch-size agnostic — it works identically during training and inference, even with a single position.

Why normalise at all?

The residual sum x + sublayer(x) can have any scale — it grows as signals accumulate across 4 blocks. Without normalisation, activations drift: small values vanish into irrelevance, large values saturate non-linearities. LayerNorm re-centres each token’s 256 features to μ≈0, σ≈1 before the learned γ/β rescales them. This keeps gradients healthy and training stable across all 4 stacked Transformer blocks.
